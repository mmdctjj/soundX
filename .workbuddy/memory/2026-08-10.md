## 修复 harmony 端 ErrorState 页面 [object Object] 问题

用户截图：标题"错误" + 内容"[object Object]" + 按钮"重试"，命中 MainPage/LibraryPage/PersonalPage 共用的 ErrorState() 模板（`Text(this.error)`）。

根因：HarmonyHttpClient.ets 第 114 行（envelope code !== 200 分支）把后端响应里的 `env.message` 直接 `new HttpError(status, message)`。`env.message` 形参类型是 string，但运行时后端可能返回嵌套对象/多语言结构（如 `{ zh: '...', en: '...' }` 或 `{ code: 401, text: '...' }`）。HttpError 继承自 Error，`super(message)` 把对象赋给 `this.message`，到页面 `Text(this.error)` 渲染就成 `[object Object]`。

附加坑：第 81 行 `new HttpError(0, String(e))`，如果 `e` 是非 Error 的普通对象，`String(e)` 也是 `"[object Object]"`，再次炸渲染。

修复（features/network）：
- HttpError.ets：新增 `safeStringify(value, fallback)` 工具函数（string 直返、null/undefined 走 fallback、其他 JSON.stringify、循环引用 fallback）；constructor 内部用 safeStringify 兜底 message，`this.message` 永远保证是字符串。
- HarmonyHttpClient.ets：(1) 第 81 行 `String(e)` → `safeStringify(e, 'request failed')`；(2) 第 114-126 行 envelope message 提取时先 safeStringify；(3) 引入 `safeStringify`。
- 调用方（各 page 的 `e instanceof Error ? e.message : String(e)`）不用改 —— HttpError.message 现在永远是 string。
