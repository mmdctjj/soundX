## mobile 小爱音箱页一直 loading（已修复）

- 现象：mobile 进 mi-speaker 一直转圈（>1min），mini/hm/desktop 正常。
- 根因：`apps/mobile/app/mi-speaker.tsx` 父组件 `MiSpeakerScreen` 的 `loggedIn` 初始 `null` 时直接 return loading，`LoginTab`（内部才有 `checkStatus`）只在 `loggedIn === false` 时才挂载 → 死锁，`onAuthChange` 永远没人调。
- mini 版父组件是自己 `checkAuth()` 主动查的，注释里还专门写了这个坑；mobile 漏抄。
- 修复：父组件加 `checkAuth` + `useEffect(checkAuth)`，与 mini 对齐。
- 排查弯路：先怀疑服务器 `/mi` 代理（localhost:3000 本地 mi 服务没起返回 504，属干扰项），后确认外网 cloud.audiodock.cn 接口正常。
- 附带发现：iOS 模拟器崩溃报告（`~/Library/Logs/DiagnosticReports/AudioDock-*.ips`）显示 8/31 两次 Hermes HadesGC 段错误——本地 Pods 自 7/27 未更新，需重跑 `pod install`。

## mobile iOS 模拟器 EXC_BAD_ACCESS（removeClippedSubviews / Fabric）

- 现象：iOS 模拟器打开/进入播放列表页崩溃，SIGSEGV / KERN_INVALID_ADDRESS。
- 栈：`updateClippedSubviewsWithClipRect:relativeToView:` 递归 → `convertRect:toView:` → `objc_retainAutoreleasedReturnValue` 野指针（0x2000000000003f00）。
- 根因：`apps/mobile/app/playlist/[id].tsx` 的 FlatList 显式开了 `removeClippedSubviews`（缩写=true）。RN 0.81 新架构(Fabric)下该优化有 bug，会把子视图摘出层级后 remount 时引用已释放 view 崩溃。RN 0.81 iOS 上 `removeClippedSubviews` 默认已是 false（`shouldUseRemoveClippedSubviewsAsDefaultOnIOS` 默认 false），全仓库仅此一处显式开启。
- 修复：改为 `removeClippedSubviews={false}` 并注释说明。长列表节点优化靠已有的 windowSize/initialNumToRender/maxToRenderPerBatch 即可。
- 注意：这是与 8/31 的「Hermes HadesGC 段错误（需重跑 pod install）」不同的第二个崩溃源，两者都要处理。

## feat-test 流水线 Tauri 插件版本不匹配（CI 报错）

- 现象：`tauri build` 阶段报 `tauri-plugin-http (v2.5.9) : @tauri-apps/plugin-http (v2.6.0)` 版本 mismatch。
- 根因：`apps/desktop/package.json` 里 6 个 tauri 插件 NPM 包都写宽约束 `^2.0.0`，CI 的 `pnpm install`（不带 `--frozen-lockfile`）重新解析时把 http 拉到最新 2.6.0；而 Rust 侧 `Cargo.lock` 锁的是 crate 2.5.9，minor（5.9 vs 6.0）不一致触发 Tauri 校验失败。
- 修复：把 `apps/desktop/package.json` + `pnpm-lock.yaml`（desktop importer specifier）里 6 个插件全部 pin 到与 `Cargo.lock` crate 一致的精确版本：autostart 2.5.1 / dialog 2.7.1 / fs 2.5.1 / http 2.5.9 / os 2.3.2 / shell 2.3.5。
- 注意：`@tauri-apps/api`/`@tauri-apps/cli`（^2.0.0）不在 mismatch 检查范围，未 pin；`tauri-plugin-opener` 仅 Rust 侧（Cargo.toml），NPM 侧无对应包，无需处理。
