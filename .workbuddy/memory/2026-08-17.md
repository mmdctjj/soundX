## ArkUI 关键约束（hm 端踩坑）

- `promptAction.showDialog` 不返回 button index（`ShowDialogSuccessResponse` 无 `buttonIndex` 字段）。需要区分「取消/确认」时必须用 `bindContentCover` + `@Builder` 自定义弹窗，参考 `SettingsPage.deleteMemberConfirmCover`。
- `router.replaceUrl` 对未注册路由是**静默 noop**，不抛错不打日志，是「loading 结束但页面不动」的根因。改用 `try { router.replaceUrl(...).catch(...) }` 显式感知失败。
- ArkTS 严格模式禁用 utility type（`ReturnType<>`、`Partial<>`等）与 `typeof` 操作符的某些用法（错误码 10605138 / 10605060）。同时 `Promise.all(arr.map(fn))` 在 ArkTS 严格模式下会把 array 元素推导成 `Promise<Promise<T>>`。**安全模式**：先 `const promises: Promise<T>[] = arr.map((x): Promise<T> => fn(x))` 显式声明，再 `await Promise.all(promises)`。
- **`$$this.xxx` 双向绑定语法**：**只**用于 ArkUI 内置 API `bindSheet / bindContentCover` 的第一个参数（参考 `AlbumDetailPage.ets:181 bindSheet($$this.showMoreSheet, ...)`、SettingsPage 的 `bindContentCover($$this.deleteMemberConfirmVisible, ...)`）。
  **自定义子组件不要用 `$$this`**——父 `@State` + 子 `@Link`，父直接传 `this.xxx`（不带 `$$`）就是双绑。子用 `@Prop` 写 `$$this.xxx` 会运行时报 `$$this is not defined` 直接闪退。
  校验：HM 端 `$$this` 出现位置全部是 `bindSheet/bindContentCover` 内置 API，不在自定义子组件里。

## XiaoAiIcon 颜色踩坑（hm 端）

- 现象：`ArtistDetailPage` / `AlbumDetailPage` 的小爱图标在亮色模式显示为白色（应该是黑/灰）。
- 根因：`XiaoAiIcon.ets` 的 `tintMatrix` 把 `parseInt(hex, 16)` 得到的 0-255 整数直接塞进颜色矩阵，但 HarmonyOS `Image.colorFilter` 的 4x5 矩阵要求 **0-1 范围的浮点数**（官方示例用 `0.33 / 0.5 / 1.0`）。
- 后果：传 `c[0] = 102` 会被当作 102.0，clamp 到 1.0 → R'=1.0 → 全白。无论传什么 `color` 都是白。
- 修复：`hexToRgb` 返回值改为 `r / 255, g / 255, b / 255`，保留 alpha 的 `a_4 = 1` 不变。
- 教训：写 ArkUI 自定义滤镜 / 矩阵 API 时，先确认矩阵值的范围（整数 vs 浮点、范围 0-255 vs 0-1）。

## AddToPlaylistModal 弹层位置 + 主题跟随踩坑（hm 端）

- 现象 1（位置）：弹窗底部停在 mini 播放器上面（GlobalBottomBar），不像 MoreSheet 那样浮在最底层。
- 现象 2（白底）：dark mode 下弹窗还是白背景（始终是 light 主题的 card 色）。
- 根因：弹窗是被父页面用 `if (this.addToPlaylistVisible) { AddToPlaylistModal(...) }` + `.position({x:0,y:0}).width('100%').height('100%')` 强制定位的普通子组件（Navigation 容器内绘制，被 BottomBar 压住，且 Modal 内部硬编码 `buildTheme('light')`）。
- 修复：让 Modal 自己用 ArkUI 内置 `bindSheet($$this.visible, this.sheetBody(), {...})` 弹（参考 `AlbumDetailPage.ets:181` 的 MoreSheet 写法）。同时 Modal 加 `@StorageLink('themeMode')` 跟随主题，sheetBody 的背景由 `bindSheet.backgroundColor: this.theme.colors.surface` 提供。
- 父页面同步移除 `.position/.width/.height`，保留 `if (this.addToPlaylistVisible)` 包裹（让 Modal 重建时重新挂 bindSheet 锚点，重新触发动画 + fetchPlaylists）。
- 教训：
  1. **底部弹层统一用 `bindSheet`**：手写 `Column + 半透明遮罩 + justifyContent(FlexAlign.End)` 这种方案位置不可控（被 Navigation/BottomBar 限制），且与 `bindSheet` 的系统动画/拖拽条体验不一致。统一用 `bindSheet` 才能保证跨页面位置行为一致。
  2. **任何自定义 @Component 里的「主题」都要 `@StorageLink('themeMode')` 跟系统**：不要 `buildTheme('light')` 写死，否则 dark mode 下永远是浅色色板（这次的白底就是这个原因）。
