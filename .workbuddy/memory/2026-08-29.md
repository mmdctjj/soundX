## 排查 hub.audiodock.cn 镜像拉取极慢（NAS 42 分钟 / 本机 24 分钟）

### 结论：服务端全局出口带宽被限制在 ~3.4 Mbps，是硬瓶颈

在 Mac 上做了三轮实测（非猜测）：

| 实验 | 结果 |
|---|---|
| 单连接 curl 拉最大层 | 430 KB/s |
| 经 Clash 代理 vs 直连 | 420 KB/s vs 407 KB/s — **无差异，代理不是瓶颈** |
| **4 连接并行** | 聚合 **409 KB/s**，每条仅分到 73~191 KB/s — **全局带宽上限，非每连接限速** |
| 完整 docker pull | 跨 3 轮累计约 19.5 分钟下完 625.7 MB |

**关键推论：提高 `max-concurrent-downloads` 无效**（并发只是平分同样的 430 KB/s）。

### 「下载到 80% 就卡住」的成因 —— 巨层长尾

arm64 镜像 33 层 / 596.7 MiB 压缩、2.52 GB 解包后，层大小极度不均：

- 第 1 层 **273.6 MiB = 总量 46%**
- 前 3 层（273.6 + 111.6 + 77.3）= **总量 77.5%**
- 其余 30 层合计仅 32.5 MiB（5.5%）

所以：小层秒下完 → 进度快速爬到 ~20% → 只剩 3 个巨层慢慢爬；到 **~80% 时并发从 3 塌缩到 1**（只剩那个 273.6 MiB 层在传），观感就是「卡住」。该层在 430 KB/s 下单算就需 **11 分钟**，这是硬下限。

### 服务端架构缺陷（响应头实证）

- 链路：`客户端 → Caddy(443) → Harbor nginx → ECS 系统盘`
- blob 返回 **HTTP/2 200 直出，无 307 跳转对象存储** → 625 MB 全走 ECS 公网带宽
- Harbor `external_url` 未正确配置：`WWW-Authenticate: realm="http://39.106.11.191:8080/service/token"`
  （明文 + 裸 IP + 8080，应为 `https://hub.audiodock.cn`）
- ECS `39.106.11.191`（阿里云北京），公网带宽约 3~4 Mbps

### 本机 Docker 代理配置（重要坑）

`~/.docker/daemon.json`：
```json
"proxies": { "default": {
  "httpProxy": "http://127.0.0.1:7890",   // Clash Verge
  "httpsProxy": "http://127.0.0.1:7890",
  "noProxy": "localhost,127.0.0.1,*.local"   // 未排除 hub.audiodock.cn
}}
```
- 吞吐上无影响（Clash 规则模式，国内直连）
- **但 Clash 一停，docker pull 6 分 32 秒零字节进度**（daemon 仍指向 7890 却无人监听）→ 单点故障
- 建议 `noProxy` 加上 `hub.audiodock.cn,.audiodock.cn,39.106.11.191`

### 已排除的因素

- DNS 24ms / TLS 握手 165ms — 控制面健康
- 磁盘：宿主机剩 50G，Docker.raw 逻辑 460G 但**实际仅占 1.4G**（稀疏文件）
- `.dockerignore` 已正确排除 `video/`(610M)、`node_modules`(2.8G)、`venv`

### 后续优化方向（按性价比）

1. **服务端接 OSS/CDN 做 307 跳转** — 唯一能突破带宽上限的办法
2. **拆分 273.6 MiB 巨层** — 缩短长尾，改善观感（但不提升总吞吐，因是全局限速）
3. **瘦身镜像** — 2.52 GB 解包体积偏大，可换 slim 基础镜像
4. 修 Harbor `external_url`、去掉一层反代（Caddy/nginx 二选一）

### `avSession.LoopMode` 枚举（系统只认这 4 种，自定义模式必须就近映射）

- `LOOP_MODE_SEQUENCE` = 0（顺序播放）
- `LOOP_MODE_SINGLE` = 1（单曲循环）
- `LOOP_MODE_LIST` = 2（列表循环）
- `LOOP_MODE_SHUFFLE` = 3（随机播放）
- `LOOP_MODE_CUSTOM` (11+) = 4

PlayerStore.PlayMode 一对一映射：SEQUENCE→0, LOOP_SINGLE→1, LOOP_LIST→2, SHUFFLE→3

### AudioCast 与 AudioDock 通知栏播控对比备忘

| 维度 | AudioCast | AudioDock |
|------|-----------|-----------|
| createAVSession tag | "PLAY_AUDIO" | "AudioDockPlayer" |
| activate 时机 | initAVSession 立即 | **首次真正播放**（防"空激活"） |
| setBackgroundPlayMode | 不调 | activate 后调 ENABLE_BACKGROUND_PLAY |
| 元数据下发 | 每 setAVMetadata 都下发 | **指纹去重**（id+title+artist+album+duration） |
| 封面 | 同步本地资源 | **异步 http → PixelMap → 补发** |

| 监听事件 | play/pause/stop/seek | + playNext/playPrevious/setSpeed |
| 后台长时任务 | BackgroundMode.AUDIO_PLAYBACK 枚举 | ['audioPlayback'] 字符串数组（API 18+ 等价） |

## mobile 我的页面小爱入口图标始终白色（2026-08-29 15:40）

- **症状**：用 `useColorScheme` + `xiaoaiLight` / `xiaoaiDark` 两张 PNG 切换 → 实际永远显示白色
- **根因**：`<Image>` 在 RN 里**不根据 `color` 渲染**，原 PNG 又是「白底+深色细线条」图标，在浅色背景下细线条被白底糊掉看起来就是一块白方块；深色背景下深色线条更看不见。**两张 PNG 本质上视觉差异很小，加 useColorScheme 切换根本没意义**
- **修复**：单张图 + `tintColor={colors.text}` 染色（按主题文字色）
  - 浅色主题：`colors.text` 深色 → 图标变深色，浅底清晰
  - 深色主题：`colors.text` 浅色 → 图标变浅色，深底清晰
  - 删 `useColorScheme` import、`xiaoaiLight` / `xiaoaiDark` 双 require、`xiaoaiIconSource` 派生变量，简化成 `const xiaoaiIcon = require("../../assets/images/xiaoai_light.png")` 单图
- **复用要点**：RN 单色图标组件的「动态主题色」标准范式 = 单张带 alpha 通道 PNG + `tintColor={colors.text}`。**不要**按主题切两张 PNG（色差难调，效果差）。

## harmony `arkts-no-spread` 编译失败（2026-08-29 15:50）

- **症状**：optimistic update 写 `{ ...k, enabled: isOn }` → `10605099 ArkTS Compiler Error: It is possible to spread only arrays or classes derived from arrays into the rest parameter or array literals (arkts-no-spread)`，文件 `MiSpeakerPage.ets:208:26` 和 `:216:28`
- **核心结论**：ArkTS `arkts-no-spread` **禁对象 spread**（`{ ...x }`），但**允许数组 spread**（`[...arr, x]`）。所以 `SyncStore`/`PlayerStore`/`AlbumDetailPage` 等源码里的 `[...this.queue, x]` 能编过，本次的 `{ ...k, ... }` 撞红
- **修复**：乐观更新改为逐字段显式构造：
  ```typescript
  this.keywords = this.keywords.map((k): MiKeywordType => {
    if (k.id !== kw.id) return k;
    const next: MiKeywordType = {
      id: k.id, keyword: k.keyword, enabled: isOn,
      created_at: k.created_at, updated_at: k.updated_at,
    };
    return next;
  });
  ```
- **关键坑**：必须列全 `MiKeyword` interface 的全部字段（id/keyword/enabled/created_at/updated_at），否则 ArkTS 严格对象字面量类型检查会报缺字段

## mini 一直 loading 死锁（2026-08-29 15:58）

- **症状**：mini 端 mi-speaker 页面一直显示 "加载中"，永不进入扫码或 3-tab 视图
- **根因**：父组件 `MiSpeaker` 在 `loggedIn === null` 时**只渲染 loading 不渲染 `<LoginTab>`**，而 `getMiAuthStatus()` 调用被错误地放在 `LoginTab` 内部的 `useEffect` —— 父组件初始 `null` 永远不渲染 LoginTab → LoginTab 不 mount → 内部 effect 不跑 → 没人调 API → `loggedIn` 永远是 `null` → 永远 loading。**死锁**
- **desktop 端有完全相同的 bug**（`<Spin />` 一直转），mobile/harmony 不受影响（mobile 默认 activeTab='login' 一开始就渲染 LoginTab，harmony 顶层 `aboutToAppear` 直接调 `checkAuth`）
- **修复**：父组件自己 `useEffect` 调 `getMiAuthStatus()` 检查登录态，结果决定渲染分支；LoginTab 内部**不再**做初始检查（去掉内部 `useState<boolean|null>(null)` + `checkStatus` + 初始 useEffect），只维护扫码流程 + 同步登录成功结果给父组件
  ```typescript
  // 父组件
  const checkAuth = useCallback(async () => {
    try {
      const res = await getMiAuthStatus();
      setLoggedIn(res.logged_in);
    } catch {
      setLoggedIn(false);  // 任何错误都按未登录处理，避免永远 null
    }
  }, []);
  useEffect(() => { checkAuth(); }, [checkAuth]);
  ```
- **复用要点**：任何「父组件根据子组件异步结果条件渲染子组件」架构，**必须把异步检查放父组件**——否则父组件无法从初始态切换出去。父组件 catch 必须把 state 设为终态（`false`），不能保持 `null`/loading，否则仍是死锁
- **TS 校验**：mini / desktop 两端 `tsc --noEmit` 零相关报错

## mini 编译 `Cannot find module '@soundx/i18e'`（2026-08-29 16:03）

- **症状**：mini 端 `app.tsx` 编译时 webpack 报 `Cannot find module '@soundx/i18e'`，报错位置 `webpackMissingModule (._src_app.tsx:22)`（间接通过 `./i18n` import）
- **根因**：Taro webpack5-runner 默认未解析 `package.json` 的 `exports` 字段。monorepo 包 `@soundx/i18e` / `@soundx/services` 的 `package.json` 用 `exports` map（`"./import"`/`"./require"`），webpack5-runner 在 weapp 编译 target 下不识别，走 fallback `main` 失败
- **修复**：`apps/mini/config/index.ts` 加 `webpackChain` alias 直接指向 cjs entry：
  ```typescript
  webpackChain: (chain: any) => {
    const path = require('path')
    chain.resolve.alias.set('@soundx/i18e', path.resolve(__dirname, '../../packages/i18e/dist/cjs/index.js'))
    chain.resolve.alias.set('@soundx/services', path.resolve(__dirname, '../../packages/services/dist/cjs/index.js'))
  }
  ```
- **复用要点**：monorepo 子包用 `exports` 字段 + Taro webpack5 编译小程序时，必须加 alias 兜底。`require.resolve('xxx/package.json')` 找不到的小程序专用别名场景，直接用 `path.resolve(__dirname, '../../packages/xxx/dist/cjs/index.js')` 硬指
