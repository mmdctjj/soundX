## 一、策略定位与核心目标

声仓不是又一个"消费型 App"，而是一个**本地优先、开源、自托管**的音频中枢。
因此内容策略的主战场不是信息流投流，而是**技术社区信任 + 开源口碑扩散**——
让 NAS 玩家、听书党、开发者主动来 star、来部署、来安利。

**北极星指标（本期）**
- GitHub Star 增长（口碑与开发者认可的核心信号）
- 公众号「声仓」净增粉丝 & 文章在看/转发率
- 官网博客自然搜索流量（长尾部署/对比词）
- 社区有效讨论量（GitHub Discussions / 用户群提问质量）

**内容漏斗**
```
  曝光层         →  公众号/少数派/知乎/论坛 图文，建立"本地音频中枢"认知
  信任层         →  开源故事 / 架构解析 / 对比评测，建立技术信任
  转化层(软)     →  部署教程 / 下载引导 / FAQ，降低首次部署门槛
  扩散层         →  用户故事 UGC / Beta 招募 / 路线图剧透，形成社区自传播
```

## 二、品牌信息屋（Messaging House）

**一句话定位（可复用）**
> 声仓 AudioDock：把你的音乐和有声书，收进一个**完全属于你**的本地播放器。

**备选 Slogan**
- 本地优先 · 多端一体 · 开源免费 —— 你的私人音频仓库
- 不靠云，也能听遍全网资源

**四大核心价值主张（所有内容围绕这四点展开）**
1. **数据私有**：本地 / NAS 自部署，不依赖任何商业云，隐私归你。
2. **一体双听**：音乐 + 有声书双模式无缝切换，进度各自记忆。
3. **随意接入**：Emby / Jellyfin / Navidrome / WebDAV / strm 直接入库。
4. **无缝接力**：多端多设备续播；TXT 经 TTS 一键变有声书。

**品牌语气（Voice）**
- 极客、务实、不浮夸；像朋友聊自托管方案，而不是念广告词。
- 技术准确，少用营销腔；可带点自嘲幽默（延续 README「开发不易，感谢赞赏」的亲切感）。
- 中文为主，术语保留英文（Docker / NAS / TTS / emby），照顾技术受众。

## 三、目标人群画像（社区向）

| 人群 | 特征 | 痛点 | 主触达渠道 | 内容钩子 |
|---|---|---|---|---|
| **NAS 折腾党** | 已有群晖/威联通，跑 emby/jellyfin | 现有播放器割裂、手机端体验差、隐私顾虑 | 恩山/NAS 论坛、B站图文、少数派 | 群晖 Docker 部署、多源接入 |
| **通勤听书人** | 大量有声书/网文收藏 | 平台会员贵、离线限制、换设备丢进度 | 公众号、知乎、小红书图文 | 双模式、设备接力、TTS |
| **本地优先/隐私控** | 不愿数据上云 | 商业云音乐下架、隐私泄露 | 少数派、V2EX、GitHub | 自托管、开源、数据私有 |
| **技术博主/开发者** | 数码/NAS KOL、开源贡献者 | 缺好素材、缺可安利的项目 | GitHub、掘金、B站 | 架构解析、贡献指南、Beta 招募 |

> 备注：技术博主是**放大器**——把他们服务好，内容会被二次传播。

## 六、内容生产机制（一套素材，多次分发）

```
        选题(支柱×人群)
              │
        深度长文(官网博客)
              │
   ┌──────────┼──────────┬─────────────┐

 (声仓)     (少数派等)   (Release/Discussion)  (信息图/对比表)
```

- 建立**素材库**：产品截图、部署录屏 GIF、功能对比表、用户好评截图。

- 设立**选题看板**（Notion/飞书均可）：草稿→评审→发布→数据回收。

## 十、风险与协同建议

1. **产能风险**：图文虽快，但每周 2-3 篇需固定排期；建议先用模板化降低单篇成本。
2. **社区预期管理**：开源项目易被提需求/报 Bug，内容语气保持透明、 roadmap 如实披露。
3. **与产品节奏对齐**：`release:beta` 与"文件数据源"等新功能上线时，内容提前 1 周预埋预告，发版当天引爆。
4. **避免硬广感**：技术社区反感营销腔，对比文客观、承认局限，反而更可信。
