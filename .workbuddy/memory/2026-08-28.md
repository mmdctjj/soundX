## mi 504 真凶：Python 3.9 不支持 PEP 604

- **实际报错**：`TypeError: Unable to evaluate type annotation 'str | None'`（pydantic v1 的 `eval_type_backport` 在 Python 3.9 不支持 PEP 604 `X | None`）
- **触发**：重构镜像 build 后，`main.py:26` import `management`，management.py 是新文件，里面 `KeywordUpdate(BaseModel)` 用了 `keyword: str | None = None` —— pydantic 静态求注解时炸
- **修复**（最小改动，只动 management.py）：
  - `from typing import Optional`
  - `keyword: str | None = None` → `Optional[str] = None`（含 `KeywordUpdate` 字段、`list_conversations` / `list_casts` 的 `Query` 默认值）
- **未改**：其它文件的 PEP 604（main.py / db.py / voice_listener.py / speaker_player.py / music_library.py / xiaomi_auth.py / web_api/{player,music,auth}.py）—— 它们都不是 BaseModel，没人 inspect 注解就不会触发 backport 报错，留 PEP 604 节省改动面
- **关键判断**：`from __future__ import annotations` 让函数签名变成字符串，但 pydantic v1 走自己 `_internal/_typing_extra.py` 静态求值，不走 `typing.get_type_hints()` 延迟路径，所以 PEP 604 在 model 字段上 3.9 也照样炸
- **下一步**：`docker compose build --no-cache app && docker compose up -d`
