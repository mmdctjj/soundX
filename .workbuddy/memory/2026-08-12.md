## 18:40 — 全屏返回后其他页面也横屏（修复方向恢复）

**用户反馈**：MV 详情页全屏后点返回（系统返回键/侧滑），其他页面还是横屏。

**根因**：原来只在 `toggleFullscreen()` 退出分支调 `setPreferredOrientation(AUTO_ROTATION)`，依赖用户点"退出全屏"按钮。如果用户通过其他路径退出全屏：
- 系统返回键直接退出 MV 详情页（不经过 toggleFullscreen）
- 侧滑手势退出
- Video 组件内部触发 `onFullscreenChange(false)` 但 toggleFullscreen 没被调

这些路径都不会走方向恢复，主窗口就被永久锁定在 LANDSCAPE。

**修复（三层兜底）**：

1. **`MVDetailPage.aboutToDisappear`**（页面销毁，最高优先级）
   - 不依赖 `isFullscreen` 状态，强制 `setPreferredOrientation(PORTRAIT)`
   - 最关键的兜底，因为页面销毁就意味着用户已经离开 MV 详情页

2. **`MvVideoPlayer.aboutToDisappear`**（组件销毁）
   - 如果还在全屏，先 `controller.exitFullscreen()`
   - 再 `setPreferredOrientation(PORTRAIT)`

3. **`MvVideoPlayer.onFullscreenChange`**（响应式恢复）
   - 抽 `restorePortraitOrientation()` 方法
   - 当 `wasFullscreen && !info.fullscreen` 时调一次（即从全屏退出瞬间）
   - 覆盖系统手势触发退出的场景

**设计决策**：恢复方向用 `PORTRAIT` 而非 `AUTO_ROTATION`：
- PORTRAIT：明确强制回竖屏，UX 最稳（用户离开视频场景不应该横屏）
- AUTO_ROTATION：允许自由旋转，但用户可能误以为 app bug

权衡下来 PORTRAIT 更稳，**减少"刚回首页就是横屏"的负面体验**。`module.json5` 的 `orientation: auto_rotation` 仍然保留，让用户在首页/其他页面仍能自由旋转。

**潜在竞态**：`setPreferredOrientation` 返回 Promise，aboutToDisappear 同步返回时 Promise 可能还在 pending。但页面销毁后主窗口方向修改仍然生效（Promise 在窗口上下文里继续执行）。

## 18:50 — 全屏切布局后变竖屏（修复方向丢失）

**用户反馈**：为啥全屏加上控制功能就不是横屏了？

**根因（两层）**：

1. **时序问题**：`setPreferredOrientation` 是**异步**的（返回 Promise），但切布局（MVDetailPage.FullscreenContent 重建）是**同步**的。流程：
   - MvVideoPlayer.toggleFullscreen → setPreferredOrientation(LANDSCAPE) 异步发出
   - 同步调 onFullscreenChange → 父组件 isFullscreen=true → 同步 rebuild
   - rebuild 瞬间 window 按**当前传感器**评估方向（设备竖着举 = 竖屏）
   - 之后 setPreferredOrientation Promise 才落地，但此时 window 已经按竖屏布局了

   之前调 `controller.requestFullscreen(true)` 时有效，是因为系统拉起独立全屏窗口，那个窗口本身默认横屏，不受传感器影响。

2. **优先级问题**：`module.json5` 是 `"auto_rotation"`（跟随传感器），`setPreferredOrientation` 在 auto_rotation 下优先级不足，会被传感器方向覆盖。

**修复（双保险）**：

1. **`module.json5`**：`"auto_rotation"` → `"user_rotation"`
   - user_rotation 下 setPreferredOrientation 能强制覆盖传感器方向
   - 不影响其他页面（首页/声仓等），用户仍能旋转设备自由切换方向

2. **`MVDetailPage.setIsFullscreen(next)`**：
   - 父组件在切布局**同步**再次触发 setPreferredOrientation
   - 让 Promise 在 layout 切换前就开始排队
   - 跟 MvVideoPlayer.toggleFullscreen 内部那次一起双发，保证生效

**对比 mobile**：mobile 用 expo-video 的 `fullscreenOptions.orientation: "landscape"` 是声明式配置，跟鸿蒙异步设置方向不一样。鸿蒙的 setPreferredOrientation 模式需要「**user_rotation + 同步触发**」才能保证强制方向。

**注意**：如果设备在横屏时进入全屏，setPreferredOrientation(LANDSCAPE) 也有效（已经横屏就保持横屏）；关键是**强制覆盖传感器**的能力。

## 第二轮：修复 51 个 ArkTS 编译错误

构建报错的根本原因：**对 ArkTS strict mode 规则认识不足**。ArkTS 比 TypeScript strict 还要严很多。错误按类别整理：

### 错误类别 & 修复

| 错误码 | 规则 | 修复方案 |
|---|---|---|
| `10605040 Object literals cannot be used as type declarations` | inline `{ a: string; b: Object }` 不能当类型用 | 全部抽成 interface（`SyncEventPayload`、`SyncCommandPayload`、`SessionStartedPayload`、`InviteHandledPayload`、`PlayerLeftPayload`、`RequestInitialStatePayload`、`InviteUsersPayload`、`DeviceInfoLike`） |
| `10605038 Object literal must correspond to some explicitly declared class or interface` | inline `{}` / `{ a: 1 }` 传给 `Object` / inline-type 参数 | 显式声明 const + 类型注解，或直接传 `null` 表示无 payload（`HarmonySocketService.dispatch('connect', null)`） |
| `10605008 Use explicit types instead of "any", "unknown"` | `unknown` 也禁用 | 改用 `Record<string, Object>` 中转 |
| `10505001 Type 'object' is not assignable to type 'Track'` | ArkTS 禁止 object → interface 的 downcast，哪怕字段齐全 | 走 `buildTrackFromRaw(raw: Record<string, Object>): Track` 显式构造（白名单字段） |
| `10905112 '@Watch('visible')' can not decorate the method` | @Watch 只能装饰状态字段，不能装饰方法 | 改成 `@Prop @Watch('onVisibleChange') visible: boolean` |
| `10605114 Namespaces cannot be used as objects` | `import * as X` 不能 cast | 显式声明 interface `DeviceInfoLike` |
| `10605999 Argument of type '... Object' is not assignable to parameter of type 'Listener'` | Listener 签名是 `(payload: Object \| null \| undefined) => void`，回调签名要一致 | 回调签名改成 `(payload: Object \| null \| undefined): void => { if (!payload) return; ... }` |
| `10505001 Type '() => void' is not assignable to type '() => boolean'` | subscribe 返回类型不匹配 | 让 `SyncStore.subscribe` / `onPlayerLeft` 都返回 `() => void`（不返回 boolean） |
| `10903329 Unknown resource name 'foreground/secondary/outline/background'` | `$r('sys.color.*')` 在 harmony 项目里不存在（mobile expo 才有） | 改用 `this.theme.colors.text/secondary/surface/border`（注入 `@State theme: Theme = buildTheme('light')`） |
| `10905210 'build' method can have only one root node` | 早返回后 Stack 不算一个根 | 用 `if (this.current !== null) { ... } else { Column().width(0).height(0); }` 包在一个 Stack 里 |
| `00305015 Rollup Error Unexpected token` | 类型注解位置不对（`@Component struct SyncNotification` 语法错误） | 简化 build，去掉 nullable `as` cast 模式 |

### 关键教训

1. **object → Track 必须走白名单构造**：`as Track` 哪怕字段齐全，ArkTS 也会报 `Type '{}' is missing the following properties from type 'Track': id, title, url`。唯一安全的做法是 `buildTrackFromRaw(raw: Record<string, Object>): Track`，每个字段 `String(raw['x'] ?? '')` 显式给出。
2. **`subscribe()` 返回 `() => void` 而不是 `() => boolean`**：调用方字段统一用 `(() => void) | null`，不要为了"准确性"用 boolean，否则 ArkTS 会因"void is not assignable to boolean"报错。
3. **`@Watch` 装饰规则**：必须紧跟在 `@Prop / @State / @StorageLink / @Link` 之后装饰字段，不能装饰方法。方法名是 `@Watch('methodName')` 的字符串参数。
4. **harmony 没有 `$r('sys.color.*')`**：mobile 的 expo 习惯搬过来直接报错。需要先注入 `@State theme: Theme = buildTheme('light')` 然后用 `this.theme.colors.*`。项目其它 component（如 `XiaoAiIcon` / `GlobalBottomBar`）已经验证这个模式可编译。
5. **dispatch 空对象要传 `null`**：`HarmonySocketService.dispatch('connect', null)` 比 `dispatch('connect', {})` 安全，因为后者触发 `Object literal must correspond to some explicitly declared class or interface`。
6. **inline `payload: { ... }` 函数参数**也要抽成 interface：ArkTS 把函数参数类型的 inline literal 也算 untyped object literal，需要 `interface SyncEventPayload` 之类的显式声明。

- `apps/harmony/products/entry/src/main/ets/context/SyncStore.ets` — 所有 inline type 抽 interface；subscribe 返回 `() => void`；listener 接收 `Object | null | undefined`
- `apps/harmony/products/entry/src/main/ets/context/PlayerStore.ets` — 新增 `SyncCommandPayload` / `SyncEventPayload` / `RequestInitialStatePayload` interface；新增 `buildTrackFromRaw()` 工具；Object cast 全部走 Record<string, Object>

## 第五轮：悬浮通知 Stack height(100%) 把 controls() 挤出屏幕

**用户反馈**：「播放详情页的布局乱了，你没修复这个问题」—— 截图显示 PlayerPage 只渲染了 cover + 一个 👤 漏在外面，下方大片空白，曲名/艺人/喜欢/小爱/同步 + 进度条 + 控制行全部消失。

### 根因

`PlayerPage.ets` 的 `LocalizedContent()` 顶层是 **Column**，最后一个 child 是：

```ts
// 同步邀请通知：覆盖在所有内容之上（顶级 Stack）
Stack() { SyncNotification() }
  .width('100%').height('100%')
  .hitTestBehavior(HitTestMode.Transparent);
```

ArkUI Column 主轴分配规则下：
- header 自然高度 56
- `content()` 是 layoutWeight(1)，按理撑满剩余空间
- 8 个 bindSheet 锚点 height(0)
- **`Stack { SyncNotification() }.height('100%')`**——height 100% 是相对**父容器高度**（Column = 全屏）

**关键**：ArkUI Column 里 child 指定 height(100%) 时，会按父容器总高度计算并**强制占满**——这跟 layoutWeight(1) 抢空间，导致 layoutWeight(1) 实际拿不到剩余空间，content() 高度被压扁成接近 0。

结果：
- content() layoutWeight(1) 高度 ≈ 0 → cover 居中显示在那一小块区域
- controls()（信息行 + 进度 + 控制行）位于 content() 内部、cover 下方 → 被挤出屏幕外
- 用户看到的就是「cover 在屏幕中部 + 大片空白 + 👤 漏在外面」

### 修复

把 `LocalizedContent()` 顶层从 **Column 改成 Stack**，让 SyncNotification 作为叠层 child（Stack 子元素之间不互相挤占空间）：

```ts
Stack({ alignContent: Alignment.TopStart }) {
  // 主体内容（占满 Stack 100%×100%）
  Column() {
    this.header();
    this.content();
    // 8 个 bindSheet 锚点保留在这里（height 0 不占空间）
  }
  .width('100%').height('100%');
  
  // SyncNotification 作为顶层叠层，absolute 定位通知卡片
  Stack() { SyncNotification() }
    .width('100%').height('100%')
    .hitTestBehavior(HitTestMode.Transparent);
}
.width('100%').height('100%')
.backgroundColor(this.theme.colors.background);
```

主 Column 现在 height 100% = 全屏高度，header (56) + content layoutWeight(1) 拿剩余 = 全屏 - 56，cover 居中 + controls() 紧贴 cover 下方正常显示。SyncNotification 在 Stack 顶层叠层（与主 Column 完全重叠但视觉上不互挤），通知卡片内部用 `position({ x: 0, y: this.animTop })` 绝对定位。

### ArkUI layout 隐藏规则（写 harmony 不要再踩）

> **Column 里 child 不要用 `height('100%')`**——height(100%) 在 Column 主轴分配中跟 layoutWeight 抢空间，会把 layoutWeight child 高度压扁成 0。要做全屏悬浮层/overlay 必须用 **Stack 包裹**，让悬浮层作为 Stack 的叠层 child，跟主内容互不挤占。
