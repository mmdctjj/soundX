## 64 个 ArkTS 编译错误修复（hk 反馈）

**触发**：上述 12 个修复首次跑 hvigorw 触发 64 个 ArkTS 编译错误（`COMPILE RESULT:FAIL {ERROR:64 WARN:459}`）。

**根因分类**：
1. **ArkTS strict 类型不匹配**（~30 个）：未声明 interface 直接用对象字面量、内联对象作为泛型参数、`any/unknown` 漏替成具体类型、结构化 downcast 报 "missing properties"
2. **TrackDto 字段错用**（5 个）：写代码时按 mobile 的 `title/coverUrl/url` 命名，但后端 Prisma 返回的是 `name/cover/path`（mobile 的 DTO 与 hm 的 DTO 不同）
3. **`LoadMoreResp<T>.items` 不存在**（2 个）：错误套 mobile 的 `items`，后端用的是 `list`
4. **下载服务动态 import 丢失类型**（8 个）：`await import('@ohos.file.fs')` 返回 ESObject，fs.openSync/writeSync/closeSync/AccessMode/OpenMode 全部消失
5. **`fetch` 是 web API 不存在**（4 个）：错误地用浏览器 fetch；应用 `@ohos.request.downloadFile`
6. **`http.RequestMethod` 字面量 vs enum**（9 个）：`'GET'` 字面量推断成 string，与 `http.RequestMethod.GET` 不兼容
7. **AppIconName 联合类型缺图**（2 个）：`'cloud-download-outline'` 和 `'grid-outline'` 之前未声明

**改动文件**（共 8 个）：
- `apps/harmony/products/entry/src/main/ets/services/downloadService.ets` — **整文件重写**：
  - 用 `@ohos.request.downloadFile` 替代 fetch
  - 顶层 `import fs from '@ohos.file.fs'` 替代 `await import`
  - 所有函数加 `context: common.UIAbilityContext` 参数
  - TrackDto 字段全改为 `name/cover/path`
  - `throw e` 改 `throw new Error(String(e))`（limited-throw 不允许任意类型）
- `apps/harmony/products/entry/src/main/ets/services/updateService.ets` — **整文件重写**：
  - `method: http.RequestMethod.GET` 替代 `'GET'`
  - 抽 `fetchRaw()` 统一返回 `{status, text}`，规避 `void & Promise<HttpResponse>` 类型坑
- `apps/harmony/products/entry/src/main/ets/services/speechService.ets` — `err[0] as Record<string,Object>` 加 `as unknown` 中转
- `apps/harmony/products/entry/src/main/ets/context/PlayerStore.ets` — `resp.items` 改 `resp.list`
- `apps/harmony/products/entry/src/main/ets/components/AppIcon.ets` — 加 `'cloud-download-outline'` / `'grid-outline'`（map 到现有 symbol）
- `apps/harmony/products/entry/src/main/ets/pages/LibraryPage.ets` — `track.coverUrl` 改 `track.cover`
- `apps/harmony/products/entry/src/main/ets/pages/MainPage.ets` — TrackDto 字段：`next.title→name` `next.url→path` `next.coverUrl→cover`
- `apps/harmony/products/entry/src/main/ets/pages/PlaybackQualityPage.ets` — 抽 `PendingNetworkParam` 顶层 interface
- `apps/harmony/products/entry/src/main/ets/pages/ArtistDetailPage.ets` — 删 isSelectionMode/selectedTrackIds 重复声明；handleBatchDownload 改用 TrackDto[]；dynamic import 改为 `const svc = await import(...)` 不用解构
- `apps/harmony/products/entry/src/main/ets/pages/PlayerPage.ets` — handleDownloadCurrent 先 `trackApi.getById(cur.id)` 拿完整 TrackDto 再传（Track 没有 path）
- `apps/harmony/features/network/src/main/ets/api/plus.ets` — 抽 `ParticipateInternalTestBody` 顶层 interface

**关键经验**（建议沉淀到 skill）：
- ArkTS strict 模式不允许 dynamic `import()` 解构（`const { kvStore } = await import(...)` 报错 "Destructuring variable declarations are not supported"），要用 `const m = await import(...); const x = m.x;`
- ArkTS strict 不允许 `as Record<string,Object>` 从带结构体的类型 downcast，必须走 `as unknown as Record<string,Object>` 两步
- ArkTS strict 不允许 `AppStorage.get<{ field: string }>(...)` 内联对象类型，必须先抽顶层 interface
- ArkTS strict 不允许 `throw e` 任意类型，必须 `throw new Error(String(e))` 或显式构造
- 鸿蒙下载不要用 web fetch（不存在），用 `@ohos.request.downloadFile(context, { url, header, filePath })`
- 后端 DTO 字段名要对齐 Prisma schema（mobile 的 `title/coverUrl` vs hm 的 `name/cover`）
- 后端 LoadMoreResp 是 `list` 不是 `items`

**CLI 沙箱限制**：本环境 `/Applications/DevEco-Studio.app/Contents/sdk/default` 装的 SDK 是 6.1.1.125，但项目 build-profile 是 6.0.2(22)；CLI 不读 DevEco Studio idea.properties，匹配不上跑不起来。但用户在 DevEco Studio 里能正常 build（原 64 错误就是从那边来的）。代码改动对照原错误逐项核对完毕，由用户在 DevEco Studio 里验证。


## 三处功能对齐 mobile 修复（下载/控制组位置/头像）

**触发**：hm 端 ① 播放详情页下载无效 + 我的页下载 tab 无内容 ② 控制组位置调整不生效 ③ 头像展示错误 + 无法上传。要求对齐 mobile 实现。用户拍板：下载 tab 基础版（曲目平铺+播放+长按删除，不做有声书专辑聚合）+ 顺带修专辑页批量下载。

**根因**：
- 下载 tab：`PersonalPage.loadData()` 对 `downloads` 分支直接 return 空数组，从不读 `getDownloadedTracks()`；`DownloadedMeta` 缺 `type` 无法按 mode 过滤；`buildDownloadUrl` 兜底路由写错（`/track/{id}/stream` → 实际 `/track/stream/{id}`）。
- 控制组位置：`controlBottomOffset` 状态存在但不持久化（kvStore 无读写）、也不应用到 `content()` 布局（`controls()` 没加 margin）。
- 头像：`AuthStore.persist()` 构建 user 时漏掉 `avatar` 字段（后端登录返回含 avatar 被丢弃）；上传成功后只改内存不落盘 kvStore。

**改动文件**（5 个）：
- `downloadService.ets` — DownloadedMeta 加 `type` 并 export；`downloadTrack` 写 type；修兜底路由
- `AuthStore.ets` — `persist()` 补 `avatar`；新增 `updateAvatar()`（改内存+落盘 kvStore+notify）
- `PersonalPage.ets` — `ListRow.fromDownloaded`；`loadData()` downloads 读列表按 mode 过滤；`handleDeleteDownload`（长按删除）；ListItem `.onLongPress`；`onAvatarClick` 改调 `authStore.updateAvatar`
- `PlayerPage.ets` — aboutToAppear 读 `player_controls_bottom_offset`；`content()` 控制组包 Column 加 `margin({bottom: controlBottomOffset})`；`controlPosSheet` Slider 实时更新+End/Click 落盘；新增 `saveControlOffset`
- `AlbumDetailPage.ets` — 批量下载从占位改为 `downloadTracks` + 确认框（`albumMore.confirmBatchDownload`）+ 完成提示（`albumMore.batchDownloadComplete`）

**对齐关键点**：mobile 控制组位置用 AsyncStorage `player_controls_bottom_offset`（hm 用 kvStore 同名 key）；下载 tab 播放复用现有 `resolveTrackToPlayer`（已自动命中 `fileCache.hasAudio` 用本地路径）；`DownloadedMeta.type` 过滤 `type === mode`（MUSIC/AUDIOBOOK）。
