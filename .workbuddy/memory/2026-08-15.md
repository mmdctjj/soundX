## 设置页开关回显错误二次修复（hm 端，推翻计时窗口方案）

- **背景**：今天早些时候的 `settingsLoadGuard` 500ms 计时窗口方案不可靠——loadSettings 的 9 个 `await kvStore.get` 串行异步回填，重建可能落在窗口外，鬼影 `onChange(false)` 仍会漏进来把存储覆盖成 false。
- **新方案（彻底脱离时序）**：`SwitchRow` 的 Toggle 包一层 `.onClick(() => { this.userTouched = true })` 记录「用户点了」信号；所有 handler 第一行改调 `applyToggle(key, val)`——没有 `userTouched` 信号的 onChange 一律视为重建鬼影直接 return，有信号则消费信号（置回 false）并写存储。
- **保留**：主题开关（dark/festive）的 isOn 来自 `themeMode`（@StorageLink）不走 kvStore，无法用「是否写存储」区分，仍保留 `themeWriteGuard` 100ms 计时窗口（`setThemeMode` 触发）。
- **已验证**：`hvigor BUILD SUCCESSFUL`。
- **注意**：`audiobookMode` 的 kvStore 键是 `'playMode'`（存 'AUDIOBOOK'/'MUSIC' 字符串），与其他布尔键不同，存储写入在 handler 里单独做。

## 设置页开关回显第三次修复（hm 端，最终方案：受控 Toggle + 透明热区）

- **教训**：前两次方案（500ms 计时窗口、onClick 置 userTouched 信号）都依赖事件时序，不可靠——`.onClick` 在 Switch 型 Toggle 上很可能先于/不随 onChange 触发，导致真实点击也被当鬼影吞掉，用户实测「还是没有生效」。
- **最终方案（从根上免疫，不依赖任何时序）**：`SwitchRow` 的 Toggle **不再注册 onChange**，改成「受控展示组件」——`.enabled(false)` + `.hitTestBehavior(HitTestMode.None)` 只负责按 `isOn: value` 渲染；点击由 Stack 上叠的 52×32 透明 `Column().onClick(() => onChange(!value))` 接管。重建再多次也绝无可能误触发，因为只有用户点热区才会调 onChange。
- **清理**：所有 handler 回到「直接写存储」的最简形式（移除 applyToggle/consumeToggleClick/userTouched）；保留 `themeWriteGuard` 100ms 窗口给 dark/festive 主题开关（它们的 isOn 来自 @StorageLink('themeMode')，重建期间值未稳定）。
- **已验证**：`hvigor BUILD SUCCESSFUL`。
- **后续**：如果用户反馈「开关点了没反应」，检查热区尺寸（52×32）是否够大、是否被禁用逻辑挡住；不要再回到「给 Toggle 注册 onChange」的老路。

## 设置页开关全部点不动（第四次修复，enabled(false) 子树禁用坑）

## 微信支付「支付验证签名失败」排查

- **现象**：hm 端唤起微信后提示「支付验证签名失败」，用户已在微信开放平台绑定鸿蒙 app 信息。
- **关键结论**（三大可能根因，按概率）：
  1. **timeStamp 类型问题（鸿蒙 SDK 特有坑，最可能）**：后端 JSON 返回纯数字时间戳时前端解析成 number，而鸿蒙 SDK `PayReq.timeStamp` 要求 string，微信客户端按 number 重拼参数验签与后端 sign 不一致 → 报签名失败。微信官方社区多个帖子确认「安卓正常、鸿蒙报错」即此因，`toString()` 解决。
  2. **微信开放平台「应用签名」填错**：必须是应用签名证书（ad.p12 里 keyAlias=ad 的证书）的 SHA-256 指纹（去冒号大写）。注意 `build-profile.json5` 里 `ad.cer` / debugKey `.cer` 其实是华为根 CA（Huawei CBG Root CA G2），它们的指纹 `DF21A3C0...` **不是**应用签名证书指纹，不能填。
  3. **Bundle Name 填错**：实际 bundleName = `com.audiodock.app`（AppScope/app.json5）；PersonalPage.ets 里 `HARMONY_BUNDLE_NAME='com.audiodock.harmony'` 是错的（只影响 AppGallery 跳转，不影响微信）。
- **代码改动**：
  1. `WechatPayService.ets` `buildPayReq`：`req.timeStamp = String(payload.timeStamp ?? '')` 兜底转换 + 日志打印 `rawType` 便于确认。
  2. `EntryAbility.ets` `dumpSelfBundleInfo`：额外打印 `signatureInfo.fingerprint`（应用签名证书 SHA-256），用户可直接拿去微信开放平台核对。
- **AppID**：`wx42a4102d85be55a1`（EntryAbility.ets），scheme 回调 `wx42a4102d85be55a1://platformId=wechat` 已在 module.json5 配好。

## 发布证书 vs 调试证书（微信支付签名关键结论）

- **本质**：鸿蒙的发布签名（ad.p12）和调试签名（DevEco 自动签名）是 AGC 分别签发的**两个不同证书**，指纹不同，无法"用发布签名装真机调试"。
- **证书链**：`.cer` 文件其实是 3 个证书的链（华为根 CA + Developer Relations CA + 应用签名证书），之前误判成"根 CA"是因为 `openssl x509` 只读第一个。应用签名证书是链里第 3 个（subject 含公司名 + `Release` 或 `Development` 后缀）。
- **两个指纹（SHA-256，去冒号）**：
  - 发布证书（ad，`...Release`）：`254692586860369C411055F8FFA2A4271A0D55D5996F75A1DB032ECA3C123120` → 微信开放平台正式上架用这个。
  - 调试证书（`...Development`）：`5C29CFBD63531F87449D62CC00507F2E4E6AF267AF690028BE15294B2D090B84` → 真机测试支付阶段微信后台填这个。
- **微信支付签名切换规则**：微信后台「应用签名」是单值，测试阶段填调试证书指纹、上线阶段切回发布证书指纹（每次改可能触发重新审核）。发布 profile 不含设备 UDID，鸿蒙系统禁止发布签名本地调试安装，所以"用 ad 签名测支付"不可行。
- **补充（微信平台约束）**：微信开放平台鸿蒙应用**仅支持一个 Identifier，不支持备用签名**（Android 才支持备用签名，鸿蒙没有），改签名需重新审核（通常半小时到一天）。因此测试→上线固定要 2 次审核，无法绕过，需提前规划时间。

- **根治方案**：开关行抽成文件级独立 `@Component struct SettingSwitchRow`（@Prop label/description/value/disabled + 普通回调 onChange），自绘轨道+滑块（不注册 Toggle onChange）。独立 @Component 的 @Prop 更新走属性级 diff，子树不销毁重建，手势识别持续有效。父页面保留 `SwitchRow` @Builder 作为薄委托层，11 个调用点零改动。
- **顺带清理**：`themeWriteGuard`/`themeGuardTimer`（100ms 主题守卫）整段删除，setThemeMode 回归纯净；`aboutToDisappear` 不再清定时器。

## 设置页开关第五轮（真机日志定位，最终根治）

- **真机日志实锤**：`tap label=语音助手 value=false` 刷屏 + `voiceAssistant -> true` 每次都打，但 UI 不动。说明点击和回调都通了，问题在 **@Prop 深拷贝导致子组件永远读到旧值**（父 @State 已变 true，子组件 onClick 里 `this.value` 还是 false，每次都翻转同一个 false → 永远写 true → UI 不变）。
- **最终方案**：`SettingSwitchRow` 的 `value` 从 `@Prop` 改 **`@Link`** 双向绑定；删掉中间层 `@Builder SwitchRow`（@Builder 参数按值传递，@Link 无法穿透绑定父 @State），9 个普通开关调用点改为直接组件调用；dark/festive 两个派生表达式开关（值来自 `themeMode === 'dark'`，无对应 @State 字段可 @Link）改用 `ThemeSwitchRow` @Builder 单向回显 + 回调写 themeMode。
- **教训**：@Prop 适合「父传子展示、子不改」的场景；一旦子组件要基于当前值做翻转/编辑，必须 @Link。skill 已同步补「层 3 根因 + 失败方案第 5 条 + @Link 代码 + 中间层 @Builder 不能转发 @Link」。
