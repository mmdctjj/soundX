## 修复车机模式白屏：旧 persist 缓存缺 columnWidths

- **症状**：`Cannot read properties of undefined (reading 'cover')` at CarMode `getWidth`，页面白屏。
- **根因**：本地 `soundx-settings` 缓存已是 version 5（上一轮升过级），但里面的 `carMode` 是旧结构、没有 `columnWidths` 字段；zustand persist **只在版本变化时跑迁移**，version 没变 → `carMode.columnWidths` 是 `undefined` → `widths['cover']` 直接炸。
- **修复（两手抓）**：
  1. **代码层防御**：CarMode / CarModeSettings / App.tsx 所有 `carMode.xxx` 访问点全部改可选链 + 兜底默认值（`carMode?.columnWidths ?? {}`、`columnOrder ?? ['cover','content','lyrics']`、`mergeCoverLyrics ?? false`、`mergedDefaultView ?? 'cover'`、`carMode?.enabled ?? false`）。
  2. **强制迁移**：persist version 5→6，migrate 里补 `columnWidths` 默认值（挂独立 if，不再绑 version<=4 块）。
- **教训**：zustand persist 的 migrate 只在存储版本低于代码 version 时触发；开发期同一 version 内给分组加字段，旧缓存不会自动补，必须升 version 或代码兜底。store 新增字段时消费端永远按「可能缺字段」写。
- 验证：`apps/desktop` `tsc -b` 全绿。

## 界面缩放：改用 WebView 原生 setZoom（修复边缘遮挡）

- **问题**：容器级 `zoom` / `transform: scale` 都不会重算内部 `100vh/100vw` 布局盒，缩放后可视区域被推出视口，页面边缘被挡住。
- **正确方案**：Tauri 用 `getCurrentWebview().setZoom(uiScale)`（WebView 原生缩放，等价浏览器 Ctrl+/-，CSS 像素/vh/vw/布局全部按缩放因子重算，无遮挡）。API 在 `@tauri-apps/api/webview`（不是 window，没有 setScaleFactor）。需要 `core:webview:allow-set-webview-zoom` capability——项目 `src-tauri/capabilities/default.json` 已配置。
- **浏览器回退**：`document.documentElement.style.zoom`（根元素 zoom 会重算布局）。
- 实现位置：`App.tsx` AppContent 的 useEffect，监听 `settings.general.uiScale`。RootWrapper 里的 zoom/transform 方案已全部撤销。
- 验证：`tsc -b` 全绿。

## 界面缩放：最终方案——<html> 根元素 CSS zoom

- **结论**：浏览器式缩放（边缘不动、布局重排）的唯一纯前端正解是把 CSS `zoom` 设在 `<html>` 根元素，**不要**设在容器上、也不要用 transform。
- **原理**：`zoom` 与 `transform: scale` 的本质区别是 zoom 参与布局重算——设在 `<html>` 上后，整个文档的 vh/vw 都按缩放后视口重新解释，所有内部 `100vh` 页面（Login/Category/Collections/Folder/MvDetail 等十几处）自动适配，无需逐个改。
- **失败方案回顾**：
  1. 容器 zoom + 反向补偿宽高 → 内部 100vh 不重算，溢出遮挡
  2. 容器 transform: scale + JS 算像素宽高 → 主布局能修，但内部十几处 100vh 页面全部溢出，不可行
  3. Tauri `getCurrentWebview().setZoom()` → 其实是正确方案（WebView 原生缩放重算一切），但用户要求不用 zoom 类 API
- **最终实现**：`App.tsx` RootWrapper 的 useEffect 里 `document.documentElement.style.zoom = String(uiScale)`，卸载时清空。主布局的 `100vh/100vw` 恢复原样（zoom 会正确重算）。
- 验证：`tsc -b` 全绿。

## 桌面端封面全部不显示 — sharp ESM/CJS interop 坑

- **症状**：桌面端 `/api/image/optimize?src=...&w=170&q=75&fmt=webp` 全部返回 `{"code":400,"message":"failed to process image","data":null}`（60 字节 JSON）。DevTools 网络面板 `Type: jpeg`、`Size: 0.1kB`（其实是它嗅探 JSON 失败、视觉欺骗）。封面全部空白。
- **真凶**：`services/api/src/services/image-optimize.service.ts:5` 用的 `import sharp from 'sharp'`。sharp 0.35+ 是 ESM-first 包：
  - `dist/index.d.mts`（ESM）`export default sharp;`
  - `dist/index.cjs`（CJS）`module.exports = sharp;`（**没有 `.default` 字段**）
- TS 在项目 `module: commonjs` + 没设 `moduleResolution`（默认 `node`）下，加载的是 `dist/index.d.mts` 类型文件。`import sharp from 'sharp'` 编译产物是 `sharp_1.default(...)`，但运行时 `sharp_1.default` 是 undefined → 抛 `(0 , sharp_1.default) is not a function`，被 controller 兜底成 400。
- **不能用 `import * as sharp from 'sharp'`**——TS 推断 sharp 是 namespace 对象（不可调用），编译期 TS2349 失败。
- **不能用 `import sharp = require('sharp')`**——TS 加载的是 mts 类型文件，`sharp` 仍是 namespace、不可调用，编译期 TS2349 失败。
- **不能用 `moduleResolution: "node16"` 走 package.json exports 加载 cts**——TS 强制要求 `module` 也改成 `"Node16"`，影响整个项目，不动。
- **✅ 最终方案**：直接 `require('sharp')` + `as any`：
  ```ts
  // eslint-disable-next-line @typescript-eslint/no-var-requires
  const sharp = require('sharp') as any;
  ```
  运行时拿到函数本身（绕过 `.default` 找不到的问题），TS 类型分析也通过（any 接受所有链式调用）。链式 API（`.resize().webp().toBuffer()`）正常使用。
- **验证**：
  - `curl /image/optimize?w=170&q=75&fmt=webp` → `200 Content-Type:image/webp Content-Length:1394`
  - `curl /image/optimize?w=300&q=75&fmt=webp` → `200 Content-Type:image/webp Content-Length:4126`
  - `file /tmp/w170.webp` → `RIFF Web/P 170x170 VP8`
  - `music/cover/.optimized/e06a1c33efc10153fd9a9d5601b7ca87.webp` 等已落盘
- **附带**：诊断时临时改 controller 把 `err.message` 透传给前端，确认根因后已回滚（不要把内部错误细节暴露给前端）。
- **教训**：sharp 升级到 0.33+ 后必须用 `require() + as any`（或换 tsconfig module/node16，否则 TS 拿不到正确 CJS 类型）。这是 sharp ESM-first 设计 + TS commonjs target 的根本性 interop 问题，与项目本身的 tsconfig 设定无关。
