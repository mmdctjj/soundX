## 车机模式「前往会员页面」点击无响应（hm 端修复）

- **背景**：昨天实现的车机模式 SettingsPage VIP 门控，用户实测点击「前往会员页面」按钮没反应。
- **根因**：ArkUI ETS `promptAction.showDialog({ buttons: [{ text, color }] })` 的 button **不支持 `onClick` 字段**，必须 `await` 返回值拿到 `ShowDialogSuccessResponse.index` 判断点击的是哪个按钮（0=取消 / 1=前往会员）。原代码用 `.catch(() => undefined)` 直接 fire-and-forget，点了之后什么都不做。
- **修改**（`apps/harmony/products/entry/src/main/ets/pages/SettingsPage.ets` `handleCarModeChange`）：
  ```ts
  const result = await promptAction.showDialog({
    title: t('settings.vipOnly'),
    message: t('settings.carModeVipOnly'),
    buttons: [
      { text: t('common.cancel'), color: '#888' },
      { text: t('settings.goToMemberPage'), color: '#3F51B5' },
    ],
  }).catch((): undefined => undefined);
  if (result?.index === 1) {
    router.pushUrl({ url: 'pages/MemberBenefitsPage' }).catch(...);
  }
  ```
- **教训 / 通用规则**：ArkUI ETS 所有「点了做某事」的多按钮对话框，必须 `await` + 读 `result.index`，不能用 button.onClick。同一坑 PlayerPage 的「立即开通」按钮也存在（`PlayerPage.ets` 有注释「按 mobile 行为简单提示，跳转交由用户主动去 PersonalPage」），用户没要求改就暂不动。
- **已验证**：`hvigorw assembleHap --no-daemon` BUILD SUCCESSFUL。

## 自动横竖屏开关无效（hm 端修复）

- **现象**：SettingsPage「自动横竖屏」开关开启后，应用不会跟随系统旋转；关闭状态下只要横屏也会被强制竖屏。
- **根因**（双重）：
  1. `SettingsPage.handleAutoOrientationChange` 只写 `kvStore`，**从未调用过 `setPreferredOrientation`**，开关在 UI 层无效。
  2. `MainPage.applyOrientation(carMode)` 关闭车机模式时强制 `PORTRAIT`，**完全没用 autoOrientation 字段**——优先级链设计缺一环。
- **修复**（3 文件）：
  1. `EntryAbility.ets`：`initialize()` 末尾从 kvStore 读 `autoOrientation` 写入 AppStorage，让 MainPage 能 `@StorageLink` 订阅。
  2. `SettingsPage.ets`：
     - `@State autoOrientation` → `@StorageLink('autoOrientation') autoOrientation`
     - `loadSettings` 删除 `this.autoOrientation = await this.readBool(...)`（AppStorage 已提供）
     - `handleAutoOrientationChange(val)`：写 kvStore + 写 AppStorage + 立即调 `applyOrientationImmediate()`（不等 MainPage 重建）
     - 新增 `applyOrientationImmediate()` 复用优先级链（carMode > autoOrientation > PORTRAIT）
     - 新增 `import { window } from '@kit.ArkUI'`
  3. `MainPage.ets`：
     - 新增 `@StorageLink('autoOrientation') @Watch('onAutoOrientationChange') autoOrientation`
     - 新增 `onAutoOrientationChange()` → `applyOrientation()`
     - `applyOrientation(carMode)` 重构为无参 `applyOrientation()`，内部读两个 `@StorageLink` 字段算优先级
     - `aboutToAppear` 去掉 `if (this.carModeEnabled)` 判断，总是 `applyOrientation()`（启动态就能跟随 autoOrientation）
- **优先级链（统一在 MainPage.applyOrientation / SettingsPage.applyOrientationImmediate）**：
  ```
  carModeEnabled=true → LANDSCAPE（车机模式锁横屏，最高优先级）
  否则 autoOrientation=true → AUTO_ROTATION（跟随系统）
  否则 → PORTRAIT（锁定竖屏，默认）
  ```
- **新发现**：HarmonyOS `window.Orientation.AUTO_ROTATION` 枚举值在 SDK 22 (API 9) 编译通过，可用。
- **教训**：所有跨页面方向/布局开关，统一用 `@StorageLink` + `@Watch` + 优先级链，写在一个独立 `applyXxx()` 函数里；页面 handler 也调同一份函数，避免栈顶页面差异。
- **已验证**：`hvigor BUILD SUCCESSFUL`。

## 自动主题（跟随系统主题）开关无效（hm 端修复，第二轮）

- **第一版无效的原因**：用了 ArkUI 的 `mediaquery.matchMediaSync('(prefers-color-scheme: dark)')` 监听系统色变化 — **这是 Web 标准 API，HarmonyOS 上不会真正响应系统设置里的深浅色切换**。编译能过、`MediaQueryListener` 实例能创建、`matches` 属性也能读到值，但 `change` 事件在真实设备上根本不触发（Web 习惯容易踩的坑）。
- **正确方案**：用 HarmonyOS 自己的 `ConfigurationConstant.ColorMode.COLOR_MODE_DARK` + `UIAbility.onConfigurationUpdate(newConfig)` 回调。这是 HarmonyOS 系统级标准回调，**100% 可信**。
- **修改**（2 文件 + 1 新文件）：
  1. `context/ThemeAutoStore.ets`（重写）：
     - `import { ConfigurationConstant, common } from '@kit.AbilityKit'`
     - 删除 mediaquery 监听
     - `init(ctx: common.UIAbilityContext)`：EntryAbility 启动时注入 context
     - `setEnabled(enabled)` / `restore()`：开启时立即读 `ctx.config.colorMode` 同步到 themeMode
     - `onSystemColorChanged(colorMode: ColorMode | undefined)`：EntryAbility.onConfigurationUpdate 回调里调用，内部按 autoTheme 状态决定是否同步
     - `stop()`：EntryAbility.onDestroy 时清空 ctx
  2. `entryability/EntryAbility.ets`：
     - import 加 `ConfigurationConstant, Configuration` from '@kit.AbilityKit'
     - `onDestroy()`：新增 `themeAutoStore.stop()` 调用
     - **新增 `onConfigurationUpdate(newConfig: Configuration)` 回调**：调 `themeAutoStore.onSystemColorChanged(newConfig.colorMode)`
     - `initialize()` 末尾：替换 `themeAutoStore.restore()` → `themeAutoStore.init(ctx)` + `themeAutoStore.restore()`
  3. `pages/SettingsPage.ets`（仅注释微调）：
     - `handleAutoThemeChange` 调用方式不变（`themeAutoStore.setEnabled(val)`），注释由「mediaquery 监听」改为「onConfigurationUpdate 自动跳过覆盖」
- **类型坑**：`Configuration.colorMode` SDK 定义是 `ColorMode | undefined`（optional），必须 `?? LIGHT` 兜底，否则 ArkTS 严格模式编译失败（`Argument of type 'ColorMode | undefined' is not assignable to parameter of type 'ColorMode'`）。
- **教训 / 通用规则**：
  - **HarmonyOS 系统配置变更**（深浅色、字体大小、语言、横竖屏、density）一律走 `UIAbility.onConfigurationUpdate(newConfig: Configuration)`，**不要用 Web mediaquery**——后者只对 CSS 媒体查询生效，不会响应系统设置变更。
  - `@kit.AbilityKit` 的 `Configuration` / `ConfigurationConstant` / `ColorMode` 是标准答案。
  - 跨页面监听仍要放单例 store（仿 SyncStore），由 EntryAbility 注入 context；store 的 API 只接收外部通知 + 内部读 ctx，调用方不感知 isDark 细节。
  - Configuration.colorMode 是 optional（`ColorMode | undefined`），所有用到的地方必须兜底。
- **已验证**：`hvigor BUILD SUCCESSFUL`。

## 扫码登录改造为相机扫码（hm 端，对齐 mobile）

- **背景**：原 ScanPage 是手动输入 session id（mobile 是相机扫桌面端二维码）。用户明确选择"改为相机扫码对齐 mobile"，不走"加手动输入作为兜底"的妥协方案。
- **mobile 参考流**：`apps/xiaolu/.../app/scan.tsx`（`expo-camera` CameraView + 解析）→ claim → `app/scan-confirm.tsx`。hm 端要把 `expo-camera` 换成 HarmonyOS `ScanKit`。
- **技术栈对比**：
  | 维度 | mobile (Expo) | hm (HarmonyOS) |
  |---|---|---|
  | 扫码头 | `expo-camera` `CameraView` + 手写 QR 检测 | `@kit.ScanKit` `scanBarcode.startScanForResult`（官方 Default View） |
  | 权限 | `useCameraPermissions()` (expo) | `ohos.permission.CAMERA` + `abilityAccessCtrl.checkAccessTokenSync` |
  | 取消回调 | 手动监听 / close | 错误码 201 = 用户取消，silent |
- **关键 API**（API 10+）：
  - `canIUse('SystemCapability.Multimedia.Scan.ScanBarcode')` 设备能力检查。
  - `scanBarcode.startScanForResult(context, options): Promise<ScanResult>`：options = `{ scanTypes: [scanCore.ScanType.QR_CODE], enableMultiMode: false, enableAlbum: true }`。
  - 成功：`result.originalValue`；用户取消：rejected err.code 201。
- **权限检查的 3 个坑**（全部踩过）：
  1. `checkAccessTokenSync` 是 **2 参数**（不是 3 参数）：`(tokenId: number, permissionName: string)`，没有第三个 GrantStatus 入参。
  2. `tokenId` **不能从 context 拿**，要从 `bundleManager.getBundleInfoForSelfSync(bundleManager.BundleFlag.GET_BUNDLE_INFO_WITH_APPLICATION).appInfo.accessTokenId` 取。`bundleManager.ApplicationFlag` / `getApplicationInfoSync` 都不存在。
  3. `import { abilityAccessCtrl, common } from '@kit.AbilityKit'`；common.UIAbilityContext 用于 startScanForResult。
- **module.json5 权限声明**：
  ```json
  { "name": "ohos.permission.CAMERA", "reason": "$string:camera_permission_reason",
    "usedScene": { "abilities": ["EntryAbility"], "when": "inuse" } }
  ```
  + `base/element/string.json` 加 `camera_permission_reason` 字符串。
- **页面状态机**（`ScanPage.ets`）：
  - `unsupportedDevice`（canIUse 失败）→ 不可用文案
  - `checkingPermission`（首次进入）→ 加载态
  - `permissionGranted`（false）→ PermissionGate + "去扫码"按钮（点击拉起系统授权）
  - `permissionGranted`（true）→ 直接 `startScan()`（不弹中间页）
  - 拿到 QR → `parseScanLoginQR` + `scanLoginApi.claim` → `router.replaceUrl({ url: 'pages/ScanConfirmPage', params: { sessionId, secret } })`
- **i18n 新增键**（`scanLogin.*`）：`permissionDenied` / `unsupportedDevice`。`permissionDesc` / `grantPermission` / `aimHint` 沿用上一版命名空间。
- **构建踩坑**：WorkBuddy 沙箱隔离 + 旧构建产物 → `FSMoveObjectToTrashSync failed status -43`。解法：`hvigorw clean --no-daemon` 后重新 `assembleHap`。
- **已验证**：`hvigorw assembleHap --no-daemon` BUILD SUCCESSFUL in 9s 836ms（clean 后）。
- **教训 / 通用规则**：
  - **HarmonyOS 权限检查标配**：`bundleManager.getBundleInfoForSelfSync(...)` 取 tokenId + `abilityAccessCtrl.createAtManager().checkAccessTokenSync(tokenId, permission)`。不要尝试 `getApplicationInfoSync` 等不存在的 API。
  - **官方 Kit 优先**：能调 ScanKit 就别自己撸相机预览；startScanForResult 自带 UI、权限、取消回调，省 80% 代码。
  - **构建缓存冲突**：WorkBuddy 沙箱里如果旧产物路径变了（safe-delete 失败），先 `hvigorw clean`，别死磕 assembleHap。
  - **mobile → hm 对齐**：先看 mobile 的"扫码页 + 确认页"是不是分两页的；是的话 hm 也要分两页（ScanPage → ScanConfirmPage），不要试图塞进一个页面。
