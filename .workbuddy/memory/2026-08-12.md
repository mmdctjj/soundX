- **放在 AudioDock 项目内**：创建 `video/` 子目录而非独立项目，方便复用项目里的图片资源
- **9 个场景拆分**：Hook → 产品定位 → 多端 → 多数据源 → 双模式 → 设备接力 → 元数据 → 部署开源 → CTA

### 踩坑

3. 渲染参数：`--concurrency=2 --jpeg-quality=85` 平衡速度和质量

## TTS 旁白补做（第二轮）

### 选型
- **引擎**：edge-tts（微软 Edge 免费 TTS，无 API Key）
- **声线**：zh-CN-XiaoxiaoNeural（温柔女声·晓晓）
- **部署**：每个场景单独生成一个 mp3，按帧数对齐场景时长

### 工程改动
- 写 `video/scripts/generate-tts.py`：生成 9 段音频 → ffprobe 测时长 → 自动按比例补足到 1800f（60s @ 30fps）
- 在 `constants.ts` 加 `AUDIO` 常量（文件路径 + 帧数），重算 `SCENE` 时序：每场景 = audioFrames + padFrames
- 在 `VideoComposition.tsx` 给每个 `<Sequence>` 内嵌 `<Audio src={staticFile(AUDIO.sX.file)} />`，9 个 Scene 文件零改动

### 踩坑
1. **总时长对齐**：edge-tts 实际读速比预估快，9 段总时长 54.3s < 60s → 写脚本自动按音频长度比例分配剩余帧（pad），补足到 1800f
2. **取整误差**：int(duration*30) 累加后差 4 帧 → 把差额补到最后一个场景的 pad
3. **工作目录**：Bash 工具的 cwd 不保留，每次必须 `cd /Users/ctjj/Documents/projects/AudioDock/video &&` 才能找到 `node_modules/.bin/remotion`

### 输出
- `video/out/audiodock-promo.mp4`：60s, 1080x1920, **8.9 MB**, H.264+AAC 立体声 48kHz
- 9 段旁白 mp3 存 `video/public/audio/scene-01~09.mp3`（共 256 KB）
- 静音检测确认 9 段音频正确分布

## 第三轮：紧凑节奏（用户反馈「停顿有点久」）

### 用户原话
> 现在每个片段之间的停顿时间有点久，每个画面之间的停顿保持 1s 就行，包括动画时长

### 改动
- 把 `generate-tts.py` 的 `MIN_PAD` 全部统一为 30f（1s），只有 s9（CTA）留 133f ≈ 4.4s 方便扫码
- 文案微调短场景（s1/s2/s7/s8/s9）让总时长仍保持 60s
- 重生成 TTS → 重写 `constants.ts` 的 SCENE → 重渲染

### 节奏对比
| 段落 | 改前 | 改后 |
|------|------|------|
| s1-s8 间停顿 | 2.5-3s | **1.9s**（1s 缓冲 + 1s 出场淡出） |
| s9 CTA 收尾 | 5s | 5s（保持） |

### 输出
- `video/out/audiodock-promo.mp4`：60s, 9.1 MB

## 第四轮：完全无停顿（用户说「还是有一点久，不要停留了」）

### 改动
- `generate-tts.py` MIN_PAD 全部 0，TARGET_TOTAL_FRAMES 设为 None（视频时长=音频总长）
- `Root.tsx` DURATION_FRAMES 改为 1427f（音频总帧数）
- `constants.ts` SCENE 所有 padFrames=0
- **修复 Scene5**：原 bookOpacity 输入区间 `[switchFrame-10, +10, +30, durationInFrames-20]` = `[120,140,160,141]` 在新 durationInFrames=161 下非单调递增报错
  → 改为所有关键帧用 `Math.floor(durationInFrames * 比例)` 动态算，保证单调

### 输出
- `video/out/audiodock-promo.mp4`：**47.62s**, 7.3 MB
- 每段间静音 ≈ 0.88-0.91s（只有词间自然停顿 + 出场淡出 1s 动画）
